# 模型配置

助手跑在哪个模型上、怎么换、换的时候要注意什么。

## 1. 当前配置

| 项 | 值 |
|---|---|
| 默认模型 | `opencode-go/deepseek-v4.1-flash` |
| Provider | `opencode-go`（OpenClaw 内置插件） |
| Base URL | `https://opencode.ai/zen/go/v1/chat/completions` |
| 认证 | `OPENCODE_API_KEY`（env）+ auth profile `opencode-go:default` |
| 能力 | text + **image**（截图录入依赖） |
| 上下文 | 1000k |

查看当前状态：

```bash
openclaw models status
openclaw models list | grep opencode-go
```

## 2. 为什么从官方 DeepSeek 换到 OpenCode Go

原来直连 `https://api.deepseek.com`（官方 key，按 token 付费）。
问题是**消耗太快**：这个助手每一轮都要带上 AGENTS.md、skill 描述、
以及截图产生的图片 token，纯按量付费时成本曲线很陡。

OpenCode Go 是 `$10/月` 订阅制，DeepSeek V4.1 Flash 给 **$60/月**的额度
（约 13 万次请求/月），远超个人助手用量。超出后还能回落到 Zen 余额。

计费分峰谷（**高峰 01:00-04:00 和 06:00-10:00 UTC，周一到周五**，
其余时间含周末为平峰），平峰价是高峰的一半。

## 3. 用内置插件，不要手写 provider

OpenClaw 自带 `opencode-go` provider 插件。**不要**自己往
`models.providers` 里手写 baseUrl —— 会漏掉关键的 session header。

OpenCode Go 要求每个请求带 `x-opencode-session`，否则直接 400：

```json
{"type":"error","error":{"type":"MissingSessionID",
 "message":"Request is missing x-opencode-session and cannot be routed efficiently."}}
```

这个 header 是用来做路由优化和 prompt 缓存的（"每个对话一个稳定 ID"）。
内置插件在 `resolveTransportTurnState` 里自动注入
（用 `sessionId` 或 `turnId`），手写配置做不到这一点。

同理 `/zen/v1/`（Zen，按量付费）和 `/zen/go/v1/`（Go，订阅制）
是**两个不同的 provider**：`opencode` 和 `opencode-go`。
换成 Go 之后如果还用 `opencode/` 前缀，会走 Zen 计费而不是订阅额度。

## 4. 配置步骤

```bash
# 1. 把 key 写进 ~/.openclaw/.env（该文件在仓库外、不进 git）
echo 'OPENCODE_API_KEY=oc_sk_...' >> ~/.openclaw/.env
chmod 600 ~/.openclaw/.env

# 2. 保存 auth profile（会写进 state/openclaw.sqlite）
printf 'oc_sk_...\n' | openclaw models auth paste-api-key \
  --provider opencode-go --profile-id opencode-go:default

# 3. 设默认模型
openclaw models set opencode-go/deepseek-v4.1-flash

# 4. 重启生效
openclaw gateway restart
```

`models set` 可能提示 `not in the local model catalog` —— 这是**误报**，
本地 catalog 没同步而已，只要 `models list` 里能看到就能用。

## 5. 换模型时必查的三件事

### 5.1 视觉能力

**这个助手的核心录入方式就是截图**（消费账单、财务总览、食物照片、体检报告），
模型没有视觉能力等于整个流程废掉。

换模型前先确认 `models list` 里该模型带 `text+image` 标记：

```bash
openclaw models list | grep <你选的模型>
```

### 5.2 端到端跑一次

配置改完**必须实际发一句话**，光看配置不算数：

```bash
openclaw agent --agent main --message "只回复：切换成功"
```

### 5.3 cron 任务是否被钉死模型

定时任务如果显式指定了 `model`，换默认模型**不会**影响它。

```bash
openclaw cron list --json | python3 -c "..."   # 看每个 job 的 model 字段
```

本项目的 4 个任务（heartbeat、财务快照提醒、skill 巡检、memory-dreaming）
全部是 `(default)`，自动跟随，无需逐个改。

## 6. 直接验证 API（绕开 OpenClaw）

排查是"key/额度问题"还是"OpenClaw 配置问题"时用这个：

```bash
curl -s https://opencode.ai/zen/go/v1/chat/completions \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -H "x-opencode-session: debug-0001" \
  -H "User-Agent: openclaw/2026.9.6" \
  -d '{"model":"deepseek-v4.1-flash",
       "messages":[{"role":"user","content":"1+1=? 只回数字"}],
       "max_tokens":300}'
```

**注意 `max_tokens` 要给够**：这是推理模型，token 先花在
`reasoning_content` 上。给 20 会得到 `content: ""` + `finish_reason: "length"`，
看着像"模型坏了"，其实只是预算不够（实测 300 才够回一个 "2"）。

## 7. 踩过的坑

- **`paste-api-key` 需要交互**：直接跑会卡在 `Required`。用 `printf 'key\n' |` 管道喂进去。
- **改完不重启不生效**：命令会明确提示
  `the Gateway has not confirmed applying the provider settings`。
- **Zen 的模型列表刷新了**：执行 `paste-api-key` 后 `models list` 里会多出一批
  `opencode/*` 模型（那是 Zen 的目录）。以后者前缀区分，别选错计费通道。
- 首次执行 auth 命令时会打印插件升级 pending 的告警，属于历史状态迁移，
  不影响使用；实在在意就跑 `openclaw update repair` + `openclaw doctor --fix`。

## 8. 回滚

配置改动前都做了备份（`~/.openclaw/openclaw.json.bak-*`）。回滚到官方 DeepSeek：

```bash
openclaw models set deepseek/deepseek-flash
openclaw gateway restart
```

`DEEPSEEK_API_KEY` 一直留在 `.env` 里没删，所以随时能切回去。
