# 图表

把消费/财务数据画成图，通过飞书发出去。

## 1. 能力现状

飞书渠道**支持发送图片**（`@openclaw/feishu` 的 send 类型含 images）。
所以「让机器人回饼图/折线图」是可行的，本模块就是干这个的。

已验证：`message(action="send", mediaUrls=[...])` 能把 PNG 作为图片气泡发到飞书对话。

## 2. 架构：Python 查数 + Node 渲染

```
chart.py          查 SQLite，组织成 JSON，调用渲染器
   ↓ (JSON via tempfile)
chartgen/render.js  @napi-rs/canvas 画图，输出 PNG
   ↓
message 工具       把 PNG 发到飞书
```

### 为什么拆成两层

**纯 Python 画图不可行。** 试过自己实现 5x7 点阵字模 + 手写像素缓冲 + zlib 编码的方案，
能跑，但**中文完全没法看** —— 点阵字模要覆盖几千个汉字，不现实。
当时的妥协是「图例用英文，正文用中文」，效果很别扭。

**换成 cairo 排版就对了。** 系统里已经有 Node，`@napi-rs/canvas` 是预编译原生模块
（不用编译工具链），装上 `fonts-noto-cjk` 后中文直接可用。

所以职责这样切：Python 侧保持**零第三方依赖**（只管 SQLite 和 JSON），
渲染侧只依赖一个 npm 包。

## 3. 依赖（一次性）

```bash
sudo apt install fonts-noto-cjk        # 中文字体
cd ~/project/private-copilot/scripts/chartgen && npm install
```

`node_modules/` 已在 `.gitignore` 里排除（34MB 原生二进制），新机器上要重跑 `npm install`。

## 4. 用法

```bash
python3 scripts/chart.py pie     --from 2026-10-01 --to 2026-10-07 --out /tmp/a.png
python3 scripts/chart.py bar     --from 2026-10-01 --to 2026-10-31 --by platform --out /tmp/b.png
python3 scripts/chart.py line    --from 2026-10-01 --to 2026-10-31 --metric day --out /tmp/c.png
python3 scripts/chart.py finance --out /tmp/d.png
python3 scripts/chart.py trend   --out /tmp/e.png
```

| 子命令 | 图类型 | 数据源 |
|---|---|---|
| `pie` | 环形饼图 | `expenses` 按 `category_l1` |
| `bar` | 柱状图 | `expenses` 按 `category_l1` / `platform` / `day` |
| `line` | 折线图（带面积） | `expenses` 按天或按月合计 |
| `finance` | 三线对比 | `finance_snapshots` 的资产/负债/净资产 |
| `trend` | 折线图 | `expenses` 全部历史按月 |

成功时打印 JSON（`out` / `type` / `total` / `count` / `items` / `points`），
**agent 应当读这个 JSON 取真实数字来组织话术，而不是凭图估算。**

## 5. 渲染规格

- **960×620 逻辑尺寸，2x 超采样 → 1920×1240 输出**。飞书里放大看依然清晰。
- 中文字体 `Noto Sans CJK SC`
- 10 色调色板，色相区分明显
- 金额 ≥ 1 万显示为「X.X万」，避免数字串太长

## 6. 踩过的坑

### 6.1 不要自己造轮子（重要）

第一次让 agent 画图时，它**没有用任何现成工具**，而是：

1. `npm install @napi-rs/canvas`（自己建了个 `/tmp/chartgen`）
2. 下载 17MB 的 `NotoSansSC.ttf`
3. 手写 60 行渲染代码

图是画出来了，而且**质量比我当时用纯 Python 画的好**。但问题是：

- 全在 `/tmp`，**重启就没了**
- 只能画饼图，别的类型要重写
- 下次问又是从头来，**每次结果不一致**

**教训**：agent 在没有现成工具时会「就地造一个」。所以技能里必须明确写
「用 `chart.py`，不要自己写渲染脚本」，并且把工具做得**足够好用**，它才愿意用。

现在 `chart.py` 就是吸收了那次即兴实现的成果（cairo 渲染 + 中文字体 + 2x 超采样），
固化成可复现的工具。

### 6.2 x 轴标签重叠

朴素做法「每 N 个取一个」不够，因为：

- 标签宽度不一（`2026-10-07` 比 `26-10` 宽得多）
- **强制包含最后一个标签**时，它会和前一个撞上（间距 `step` 可能小于标签宽度）

**正确做法**（见 `render.js` 的 `drawXLabels`）：

1. 用 `ctx.measureText` 量**真实宽度**，不要按字符数估算
2. 按宽度算出最多能放几个 → 得到间隔 `every`
3. **从右往左放置**，维护 `rightLimit`；放不下就丢弃当前
4. 强制包含最后一个下标

从右往左是关键：从左往右会先占住位置，导致末尾的「最新日期」反而被挤掉或压字。

### 6.3 图例溢出画布

图例项数不固定（分类多的时候有 10+ 项），固定 `slice(0, 8)` 在项高较大时仍会溢出底部。

**做法**：按可用高度算 `maxRows = floor((底部 - 顶部) / 行高)`，超出的合并显示为
「另有 N 项未显示」。这样无论多少分类都不会破版。

### 6.4 空数据

`count=0` 时也生成 PNG（画一个「暂无数据」占位），而不是报错退出。
但**技能要求 agent 遇到空数据时不要发图**，直接文字回复 —— 发空图很蠢。
