# 消费分类词表

本文档是 `config/categories.yaml` 的可读版本，便于快速查阅。

> **唯一事实来源是 `config/categories.yaml`。** 两者不一致时以配置文件为准。
> 修改分类请改配置文件，不要改本文档。

---

## 一级分类（受控）

LLM 只能从这 10 个中选取，**不得自创**。

| 一级分类 | 含义 | 二级常用值 |
|---|---|---|
| `餐饮` | 吃饭、外卖、买菜 | 日常、社交、外卖、买菜、咖啡饮品 |
| `交通` | 通勤与出行 | 地铁公交、打车、加油、停车、高速、火车、机票 |
| `购物` | 买东西 | 日用、数码、服饰、美妆、家居 |
| `居住` | 住相关的固定支出 | 房租、房贷、水电燃气、物业、宽带 |
| `医疗` | 看病、买药、体检 | 门诊、药品、体检、牙科、保险 |
| `娱乐` | 休闲娱乐与订阅 | 电影、游戏、演出、会员订阅、旅游 |
| `学习` | 教育、书籍、课程 | 书籍、网课、培训、考试 |
| `人情往来` | 红包、礼金、赠送 | 红包、份子钱、礼物、孝敬父母 |
| `健身` | 运动相关支出 | 健身房、私教、装备、赛事 |
| `其他` | 兜底 | — |

**回退规则**：一级分类不在上表内时，自动回退到 `其他`，并置 `category_fallback = true`，必须在回复中告知用户。

## 二级分类（自由）

二级分类是**自由文本**，上表的"二级常用值"仅为保持表达一致性的参考，不是硬约束。

- 能从描述判断就填
- 拿不准就留空（数据库允许 NULL）
- 同一含义尽量用词一致，便于聚合（例如统一用"咖啡饮品"而非"咖啡"/"咖啡饮品"/"coffee"混用）

## 支出平台（受控）

与数据库 `CHECK` 约束一致，只能取以下值：

| 平台 | 说明 |
|---|---|
| `支付宝` | 含余额宝、花呗支付 |
| `微信` | 含零钱、零钱通 |
| `现金` | 线下现金支付 |
| `信用卡` | 实体信用卡、银行信用支付 |
| `其他` | 不在上述范围，或用户未说明 |

**用户未说明平台时填 `其他`，并在回复中问一句**，不要猜测。

## 变更规则

### 一级分类：只增不改

改名会切断历史数据的时间序列，导致跨期分析失效。例如把"餐饮"改成"吃喝"，历史数据仍记着"餐饮"，之后无法按同一维度聚合。

确需调整时：

1. **新增**分类，不重命名
2. 历史数据保持原样
3. 如需拆分旧分类，在查询层做映射，不改历史记录

### 二级分类：可自由演进

二级分类不影响受控维度，可以随时新增。建议新增前先查已有取值，避免同义重复：

```bash
sqlite3 data/copilot.db \
  "SELECT category_l1, category_l2, COUNT(*) n
   FROM expenses WHERE category_l2 IS NOT NULL
   GROUP BY category_l1, category_l2 ORDER BY category_l1, n DESC;"
```

### 平台：改动成本高

`platform` 有数据库 `CHECK` 约束，新增取值需要改 schema 并重建表。当前五个取值覆盖了绝大多数场景，不建议轻易扩展。

## 判断口径速查

| 场景 | 归入 | 不归入 |
|---|---|---|
| 有他人参与、金额明显偏高的就餐 | `餐饮` / 社交 | `餐饮` / 日常 |
| 药店买药 | `医疗` / 药品 | `购物` / 日用 |
| 医院挂号、体检费 | `医疗` | `购物` |
| 私教课、运动装备 | `健身` | `娱乐`、`购物` |
| 视频/音乐/云盘会员 | `娱乐` / 会员订阅 | `购物` |
| 买菜回家做饭 | `餐饮` / 买菜 | `购物` / 日用 |
| 打车去机场 | `交通` / 打车 | `交通` / 机票 |
| 机票、火车票 | `交通` / 机票、火车 | `娱乐` / 旅游 |
