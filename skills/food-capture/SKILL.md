# 食物记录

用户随手拍一张饭照发过来，存进库里。**越轻越好** —— 不要问东问西。

## 字段

| 字段 | 说明 |
|---|---|
| `id` | 自增 |
| `eaten_at` | 用餐时间 |
| `photo_path` | 照片相对路径（纯文字记录为空） |
| `note` | 备注（可选：和谁吃、哪家店） |
| `source` | `image`（照片）/ `text`（纯文字） |

## 写入

```bash
python3 ~/project/private-copilot/scripts/validate.py meal --json '{
  "eaten_at": "2026-09-30 12:30",
  "photo": "/home/ubuntu/.openclaw/media/inbound/xxxx.jpg",
  "note": "午饭"
}'
```

### 照片路径从哪来

飞书发来的图片会被 OpenClaw 存到 `~/.openclaw/media/inbound/<uuid>.jpg`，
**消息里会带这个路径**（形如 `<media:image>` 或附件引用），直接用即可。

`validate.py` 会把它**复制**到 `data/photos/YYYY/MM/`，表里只存相对路径。

> ⚠️ **为什么必须复制**：`media/inbound/` 是 OpenClaw 的暂存区，
> 重启或清理会消失。食物照片要长期留存，必须落到我们自己的目录。

### 三条规则

**① 时间可以不说。**

食物照片是"随拍随发"，用户没提时间就**默认当前时间**，不要追问。
（这与消费记录不同 —— 消费截图上有交易时间，不能让模型瞎猜。）

**② 补一个 note 就够了，不要追问。**

看到照片可以顺手写一句描述（"鸡腿 + 包子 + 青菜"），但**不要**问
"这是哪一餐""和谁吃的""好不好吃"。用户要的是快速记录，不是填表。

**③ 只记吃的，不记钱。**

食物照片**不产生消费记录**。用户可能同时说了金额（"这个外卖 35"）——
那种情况走 `expense-capture` 记一笔消费，**另外**用本技能存照片，
两条记录互相独立，不要互相引用。

## 纯文字怎么办

用户没发照片，只说"午饭吃了豆浆油条"：

```bash
python3 ~/project/private-copilot/scripts/validate.py meal --json '{
  "eaten_at": "2026-09-30 08:00",
  "source": "text",
  "note": "豆浆油条"
}'
```

纯文字记录**必须有 note**，否则这行没有任何信息，脚本会拒绝。

## 退出码

| 码 | 含义 | 你做什么 |
|---|---|---|
| 0 | 成功 | 回复 `已记录 ✅ (id=N)` |
| 1 | 校验失败 | 看 `error`（时间格式、文件不存在、格式不支持等） |
| 2 | 重复 | 这张照片已经在库里了，回 `这张已经记过了 (id=N)`，不要重试 |

## 重复照片

**同一张照片不会入库两次**（按文件内容哈希 + 路径去重）。

用户重复发同一张图（很常见：网络卡了重发、或者忘了已经发过），
脚本返回 `reason: duplicate`，你告诉用户"这张已经记过了"即可。

**不要**为了让用户满意而改个名字硬塞进去。

## 查询

```bash
# 最近 20 条 + 按天统计
python3 ~/project/private-copilot/scripts/query.py meal --limit 20

# 指定区间
python3 ~/project/private-copilot/scripts/query.py meal \
  --from 2026-09-01 --to 2026-09-30
```

返回里每条照片记录带 `photo_abs`（**绝对路径**），要发图时直接用它。

## 回复格式

写入后**一句话**就好，不要长篇大论：

```
已记录 ✅ (id=3) 午饭 · 12:30
```

带 note 时：

```
已记录 ✅ (id=3) 午饭
鸡腿 + 包子 + 青菜
```

用户想回顾时，**可以把照片发回去**（用 `message` 工具 + `photo_abs`）：

```bash
# 查出来，挑几条
python3 ~/project/private-copilot/scripts/query.py meal --from 2026-09-01 --to 2026-09-07
```

**不要**主动分析营养、热量、健康度 —— 用户没问就别说。
如果用户**主动问**"我这周吃得健康吗"，可以基于 note 做定性描述，
但**必须说明这是主观观察，不是营养学结论**。

## 与其他技能的边界

| 场景 | 走哪个 |
|---|---|
| 食物照片（吃什么） | 本技能 |
| 消费金额（花了多少） | `expense-capture` |
| 外卖订单截图（有金额） | `expense-capture`（记消费）；想留照片再加本技能 |
| 体检报告 / 化验单 | `health-report` |
| 体重 / 体脂等身体数据 | `health-report` |

一张外卖订单截图**同时有菜品和金额**时：**默认走 `expense-capture` 记消费**，
因为金额是硬信息、漏了就没了；照片是软信息。
如果用户明确说"把这张存到食物记录"，再走本技能。
